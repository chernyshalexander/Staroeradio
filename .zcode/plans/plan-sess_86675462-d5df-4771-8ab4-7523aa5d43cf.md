## План реализации Пути B с созданием ветки и тестированием API

### Этап 1: Создание рабочей ветки
```bash
git checkout -b feature/api-covers-mode
```
Название ветки: `feature/api-covers-mode` (отдельно от master и experiment)

---

### Этап 2: Тестирование API-запросов (перед кодированием)

**Цель:** Проверить что API работает и обложки релевантны

**Создать скрипт:** `test_api_requests.pl`

**Тестируемые сценарии:**
1. **Live stream — текущий трек**
   ```
   GET http://server.audiopedia.su:8888/getcurrentinfo.php
   Ожидание: XML с <staroeradio><id>...</id></staroeradio>
   ```

2. **Метаданные с обложками по track_id**
   ```
   GET http://server.audiopedia.su:8888/getradioinfo.php?cmd=getMetaInfo&track_id=X
   Ожидание: JSON с Metainfo.images[] (URL картинок)
   ```

3. **Проверка разных доменов**
   - server.audiopedia.su:8888 (.ru)
   - server.audiopedia.world:8888 (.com)

**Сохранение результатов:**
- Создать каталог: `test_results/images/`
- Скачать 5-10 обложек для проверки
- Создать отчёт: `test_results/api_test_report.txt`

---

### Этап 3: Проверка релевантности обложек

**Автоматическая проверка:**
- Проверка что URL изображений доступны
- Проверка размеров изображений (не пустые)
- Проверка content-type (image/jpeg, image/png)

**Ручная проверка (если не могу распознать):**
- Сохранять изображения в `test_results/images/`
- В отчёте указывать: track_id, название, URL изображения
- **Запросить подтверждение релевантности у пользователя**

**Критерии успеха:**
- ✅ API-запросы возвращают 200 OK
- ✅ JSON/XML корректно парсятся
- ✅ Обложки скачиваются
- ✅ Обложки релевантны трекам (подтверждено пользователем)
